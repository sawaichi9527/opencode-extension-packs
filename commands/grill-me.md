針對下列主題進行需求訪談：

$ARGUMENTS

若沒有提供參數，使用目前對話中正在討論的計畫、功能或設計作為主題。

請遵守以下流程：

1. 先讀取專案的 `AGENTS.md`、`handoff.md`、相關文件、程式碼與 Git 狀態，能由 Repository 或工具查明的事實不要反問使用者。
2. 只詢問需要由使用者決定的事項，而且每次只問一題，等待回答後再繼續。
3. 每一題都附上你的建議答案與簡短理由，但最終決定由使用者確認。
4. 優先釐清：目的、範圍、不包含範圍、限制、成功條件、失敗條件、驗證證據、錯誤處理、介面、資料流、DUT／硬體影響與安全邊界。
5. 遇到「正常、完成、成功、失敗、Log、封包、Timeout、支援」等可能有多種解釋的詞，必須轉成可觀察、可測量或可驗證的定義。
6. 對 Python、UART／TTY、Console Log 或 Wireshark／PCAP 工作，確認原始證據、Parser 結果、時間基準、Verdict 與 Artifact 保存方式。
7. 不要為了訪談新增 `CONTEXT.md`、ADR 或其他文件流程。只有使用者明確要求保存結果時，才使用專案既有的文件結構。
8. 在雙方確認已達成共同理解前，不建立程式碼、不修改檔案，也不開始實作。

訪談完成時，整理：

- 目的
- 範圍
- 不包含範圍
- 已確認的重要術語
- Acceptance Criteria
- 必須保留的驗證證據
- 重大決定與理由
- 尚未確定事項
- 建議的下一步

顯示摘要後等待使用者確認，不要自行進入實作。
